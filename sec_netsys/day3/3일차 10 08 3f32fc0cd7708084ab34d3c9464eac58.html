진행 과정

  1. PC A 판단 : A→B, B가 같은 네트워크인가? → 아님 → Gateway로 보내야함 → Gateway(1.1)의 MAC addr 을 모름
    실행 : ARP Request, Broadcast [ 1.1(G/T)의 MAC addr을 찾습니다]
    구간Src MACDst MACSrc IPDst IP
    A→RAAFFFF.FFFF.FFFF1.10(A)1.1(RA f0/0)
  1. RA 판단 : 내가 1.1(G/T)인가? → 맞음
    실행 : ARP Reply, Unicast [내가 1.1(G/T)입니다]
    구간Src MACDst MACSrc IPDst IP
    RA→ARA f0/0A1.1(RA f0/0)1.10(A)
  1. PC A : DestMAC을 알아냈다 → 게이트웨이로 ICMP를 보냄
    실행 : ICMP Echo Request
    구간Src MACDst MACSrc IPDst IP
    A→RAARA f0/01.10(A)2.10(B)
  1. RA 판단 : S 2.0 via 12.2 매칭 → 12.2(RB f0/1) MAC을 모름
    실행 : ARP Request
    구간Src MACDst MACSrc IPDst IP
    RA→RBRA f0/0FFFF.FFFF.FFFF12.1(RA f0/0)12.2(RB f0/1)
  1. RB 판단 : 내가 12.2인가? → 맞음 (RA의 IP/MAC을 캐시에 저장)
    실행 : ARP Reply, Unicast [내가 12.2입니다]
    구간Src MACDst MACSrc IPDst IP
    RA→RBRA f0/0FFFF.FFFF.FFFF1.1(RA f0/0)1.10(A)
  1. RA : 다음 홉 MAC을 알아냈다 → RB로 ICMP 전달 (TTL 128→127)
    실행 : ICMP Echo Request
    구간Src MACDst MACSrc IPDst IP
    RA→RBRA f0/1RB f0/11.10(A)2.10(B)
  1. RB 판단 : C 2.0 (f0/0 직접 연결) 매칭 → 최종 목적지 2.10(B)의 MAC을 모름
    실행 : ARP Request, Broadcast [2.10의 MAC addr을 찾습니다]
    구간Src MACDst MACSrc IPDst IP
    RB→BRB f0/0FFFF.FFFF.FFFF2.1(RB f0/0)2.10(B)
  1. PC B 판단 : 내가 2.10인가? → 맞음 (RB f0/0의 IP/MAC을 캐시에 저장)
    실행 : ARP Reply, Unicast [내가 2.10입니다]
    구간Src MACDst MACSrc IPDst IP
    B→RBBRB f0/02.10(B)2.1(RB f0/0)
  1. RB : B의 MAC을 알아냈다 → B로 ICMP 전달 (TTL 127→126)
    실행 : ICMP Echo Request
    구간Src MACDst MACSrc IPDst IP
    RB→BRB f0/0B1.10(A)2.10(B)
  1. PC B 판단 : 1.10(A)이 같은 네트워크인가? → 아님 → Gateway(2.1)로 보내야 함 → 8단계에서 MAC을 이미 앎 (ARP 생략)
    실행 : ICMP Echo Reply
    구간Src MACDst MACSrc IPDst IP
    B→RBBRB f0/02.10(B)1.10(A)
  1. RB 판단 : S 1.0 via 12.1 매칭 → 12.1(RA f0/1)의 MAC은 5단계에서 이미 앎 (ARP 생략)
    실행 : ICMP Echo Reply 전달
    구간Src MACDst MACSrc IPDst IP
    RB→RARB f0/1RA f0/12.10(B)1.10(A)
  1. RA 판단 : C 1.0 (f0/0 직접 연결) 매칭 → 1.10(A)의 MAC은 2단계에서 이미 앎 (ARP 생략)
    실행 : ICMP Echo Reply 전달 → A 도착 (TTL=126)
    구간Src MACDst MACSrc IPDst IP
    RA→ARA f0/0A2.10(B)1.10(A)

Routing Protocol의 분류

Distance Vector / Link-state

Distance Vector (loop방지 기술6개) : basic : RIP, 하지만 그래도 루프발생함

Advanced Distance Vector : BGP의 기본 알고리즘(=Distance Vecotr) + 자기만의 Loop방지책 추가

Link-State : OSPF(가장많이 사용되는 Routing Protocol) : 안정적 절대 loop발생 x → 중대형망 사용가능 → 큰 메모리, 경로계산cpu필요 → 리소스가 많이 요구된다.

가상화, 클라우드에서 Routing Protocol → BGP가 기본
